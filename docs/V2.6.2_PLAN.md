## A1 — Uçuşu gerçek motora/projeye bağla (ANA İŞ)

**Sorun:** `launch_site.html:392-398` "Fly this site" sabit bir demo roket
uçuruyor (`dry_mass 25, thrust 6500, burn_time 7.5`). Kullanıcının tasarladığı
motorla/projeyle hiçbir bağı yok → "hangi projemi kullanıyorum" kafa karışıklığı.

**İyi haber:** 6-DOF çözücü (`six_dof_trajectory.py:227`) ZATEN `thrust_curve`
({time, thrust}) kabul ediyor — motorun transient çıktısı doğrudan beslenebilir.

**Yaklaşım:**
1. **Araç kaynağı seçimi** paneli: (a) son hesaplanan motor (oturum köprüsü),
   (b) kayıtlı `.hrma` projesi, (c) açıkça etiketli "örnek araç" (mevcut demo,
   ama artık VARSAYILAN DEĞİL — "örnek" diye işaretli).
2. Motor → itki eğrisi + propelan kütlesi + yanma süresi otomatik gelir
   (transient analizi çıktısı). 
3. **Airframe** (gövde çapı/uzunluğu, burun, kuru kütle, kanatlar, Cd,
   kalkış açısı/azimut) motor tarafında yoksa launch-site'ta küçük bir araç
   paneliyle girilir; makul varsayılanlar + "?" ipuçları. `.hrma` projesinde
   varsa oradan doldurulur.
4. Üstte net etiket: "Uçurulan araç: <motor adı> (<kaynak>)".

**⚠️ İKİ TUZAK (codex — kod gerçeğine dayalı):**
1. **Kanatsız araç 6-DOF'ta anlamsız:** BarrowmanAero'da fin yoksa CP burna
   kayar, statik marj negatif, çözücü anında `tumble_event` ile biter
   (doğrulandı: solve() tumble_event.terminal=True). Airframe/kanat yoksa
   6-DOF KOŞULMAZ veya "kararsız/airframe tanımsız" diye AÇIKÇA etiketlenir.
   "Örnek araç" yalnız açık "örnek" etiketiyle.
2. **Kuru kütle çift-sayımı:** `dry_mass` propelanı HARİÇ tutmalı
   (dry = airframe + inert motor donanımı). Motorun "dolu kütlesi"ni dry_mass'a
   koyup ayrıca `propellant_mass` eklemek propelanı iki kez sayar. Köprüde netle.

Motor verir: `thrust_curve, propellant_mass, burn_time, engine_od (gövde çapı
alt sınırı), engine_mass, engine_length`. Airframe (burun, kanat, uzunluk,
kuru kütle, CG) kullanıcı panelinden; motor-türevi alanlar KİLİTLİ+görsel ayrım.

**Dokunulacak:** `launch_site.html`, `app.py` (motor→araç köprü ucu veya
proje okuma), `projects.py` (airframe alanları round-trip), `i18n_launch_site.js`.
**Dürüstlük:** airframe kullanıcıdan gelir; uydurma gövde/kanat üretilmez.

## A2 — 3D Dünya zoom detayı (online karo + offline fallback)

**Sorun:** `launch_site_globe.js` tek 4096px equirectangular Blue Marble
dokusu geriyor → yakınlaşınca bulanık ("bok gibi").

**İyi haber:** uygulama ZATEN online API kullanıyor (open-meteo, offline DEM
fallback'li) — "internetten çek, offline'a düş" deseni kurulu.

**⚠️ SAĞLAYICI KARARI (codex — projeksiyon farkı kritik):**
- **ESRI World Imagery:** alt-metre çözünürlük AMA **Web Mercator (EPSG:3857)**
  → equirectangular küreye drape için REPROJEKSİYON gerekir (y nonlineer,
  en sık hata), kutupları ±85.05° dışında kapsamaz, lisans gri. Preset'lerde
  **Esrange 67.9°N + Andøya 69.3°N var** → Mercator distorsiyonu yüksek.
- **NASA GIBS (SEÇİLEN):** **EPSG:4326 (equirectangular)** tile matrix →
  küre UV'sine REPROJEKSİYONSUZ oturur, NASA lisansı temiz, anahtarsız.
  ~250 m/px. **Ölçek gerçeği:** mevcut 4096px Blue Marble ≈ 9.8 km/px →
  GIBS ~40× keskin; "bulanık" şikâyetini TEK BAŞINA çözer, ESRI'ye gerek yok.
  Alt-metre pad görüntüsü yok; o gerekirse mevcut "detay yok" notu korunur.

**Yaklaşım (kademeli):**
1. Kamera yüksekliği eşiğin (TEXTURE_NOTE_ALT_M) altına inince hedef lat/lon
   çevresinde küçük EPSG:4326 **patch mesh** + GIBS tiles. TÜM küreyi yüksek-z
   ile yeniden dokuMA (tile patlaması, binlerce istek).
2. Zoom arttıkça z seviyesi (sağlayıcı max'ına clamp). Patch yaklaşımı kutup
   singularity'sini de bertaraf eder (Esrange/Andøya güvenli).
3. **Offline / 404 / sağlayıcı hatası → Blue Marble'da kal** + "detay yok" notu.
   Sahte arazi ÜRETİLMEZ.
4. **KALICI YEREL DİSK ÖNBELLEĞİ (Berke isteği 2026-07-24):** İnen karolar
   DİSKTE kalır, her seferinde yeniden inmez, bir kez baktığın bölge sonradan
   OFFLINE çalışır. Küçük backend önbellek ucu: JS `/api/tile/{z}/{x}/{y}`
   ister → backend yerel önbelleği (Belgeler/HRMA/tiles veya app cache dizini)
   kontrol eder → yoksa GIBS'ten çeker, diske yazar, döner. (Bu, codex'in
   "CORS için proxy gereksiz" tespitini değiştirmez — bu proxy CORS için değil,
   KALICI ÖNBELLEK için. İkisi farklı gerekçe.)
   - **Boyut gerçeği:** talep-üzerine tek oturum ~5-30 MB. Diskte YALNIZ
     baktığın bölgeler birikir — yüzlerce MB DEĞİL, aylarca kullanımla belki
     onlarca-birkaç yüz MB (yalnız gezdiğin yerler). Önbellek boyut tavanı +
     "önbelleği temizle" düğmesi eklenir.
   - **Önden dev indirme YOK** (uygulama boyutu şişmez); kurulum aynı kalır.
5. **Offline algısı:** fetch/önbellek ikisi de başarısız → Blue Marble'da kal
   + "detay yok" notu.

**Dokunulacak:** `launch_site_globe.js` (ana iş) + yeni tile modülü + `app.py`
(kalıcı önbellek ucu). **Risk:** grafik işi; EPSG:4326 patch UV hizası dikkat
ister (ama Mercator'dan çok daha kolay). **Dürüstlük:** yalnız gerçek uydu
görüntüsü; önbellek şeffaf (kullanıcı temizleyebilir).

## B1 — Coriolis 6-DOF (dürüstlük + A ile sinerjik)

**Sorun:** `six_dof_trajectory.py` düz-Dünya atalet çerçevesinde;
`launch_site.py:108 NOT_MODELLED['earth_rotation']` ile Dünya dönüşü/Coriolis
beyan-dışı. Yer izi düz-Dünya izdüşümü — GPT'nin "çekirdek eksik" bulgusu.

**İyi haber:** `OMEGA_EARTH = 7.292115e-5` zaten tanımlı. Çerçeve = fırlatma
noktasına çapalı teğet-düzlem (x0=Kuzey, x1=Doğu, x2=Yukarı); ECI/ECEF'e
GEÇMEYECEĞİZ (sounding-roket kapsamı için gereksiz). Yalnız Coriolis eklenir.

**⚠️ KRİTİK — EL-YÖNÜ (HANDEDNESS) BUGI (codex xhigh yakaladı, doğrulandı):**
Fiziksel (Kuzey,Doğu,Yukarı) üçlüsü **sol-ellidir** (N×E = −U), ama `np.cross`
sağ-elli sayar. Bugüne dek zararsızdı çünkü hiçbir terim Dünya dönüş kiralitesine
dokunmuyordu; Coriolis **ilk** dokunan. Naif `−2·cross(omega,v)` dikey atışta
DOĞU verir — fizik BATI olmalı → **işaret ters, dürüst düz-Dünya'dan DAHA KÖTÜ**.
**Güvenli kalıp:** Coriolis'i geçici sağ-elli ENU'ya çevir, hesapla, (N,E,U)'ya
geri döndür (codex'in verdiği pattern).

**Yaklaşım (düzeltilmiş):**
1. **Yalnız Coriolis** (−2Ω×v_rel), güvenli-handedness kalıbıyla.
   - MERKEZKAÇ EKLENMEZ: `local_gravity` WGS84 Somigliana zaten içeriyor →
     ayrı `−Ω×(Ω×r)` = çift sayım (doğrulandı).
   - TAŞIMA HIZI EKLENMEZ: bu çerçevede roket pad'de v_rel=0; 465 m/s'yi
     başlangıç hızına eklemek = Dünya dönüşünü iki kez sayma (o ECI kalıbı).
2. **latitude plumbing:** `SixDOFTrajectory.__init__`'e `latitude_deg` ekle
   (şu an YOK — doğrulandı); `app.py` seçili sahadan geçirir.
3. Ray fazında Coriolis ihmal (v≈0); free-flight'ta uygula.
4. `NOT_MODELLED['earth_rotation']` KALDIRILIR; globe "flat-Earth projection"
   notu güncellenir (küçük, en sonda sıralı dokunuş).

**Test (TDD — önce başarısız test, sonra kod; merge buna bağlı):**
- Dikey atış (kuzey yarıküre) → APOJEDE Doğu-konumu < 0 (batı). `solve()`
  apojede sonlanıyor (doğrulandı) → İNİŞ SAPMASI TEST EDİLMEZ.
- Büyüklük: `ΔE ≈ −(4/3)·Ω cosφ·v0³/g²` (codex teyitli).
- Coriolis iş yapmaz: `|dot(a_cor, v)| ≈ 0` birim testi.
- Yarıküre ayrımı: eğik atış (sinφ terimi N↔G işaret değiştirir).
- Mertebe: v0~1 km/s, apoje ~30 km → batı sapması ~100–200 m.

**Dürüstlük:** Coriolis, rüzgâr sürüklenmesinin (km) çok altında (~100 m);
B1 büyük etki için değil, TAMLIK/DÜRÜSTLÜK için (oversell etme).

**Dokunulacak:** `six_dof_trajectory.py` (çekirdek + latitude), `app.py`
(latitude geçişi), `launch_site.py` (NOT_MODELLED + yer izi), `launch_site_globe.js`
(yer izi etiketi), yeni testler. **Risk:** EN YÜKSEK — işaret doğruluğu TÜM OYUN.
